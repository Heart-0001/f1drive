# 賽季原始資料（2010–2026）

`tools/build-seasons.mjs` 從開放資料庫 F1DB 產生 `tools/seasons-raw.json`：17 個賽季、180 個車隊條目，
每個條目附上排位賽速度、賽道性格與年代速度指數。這份是「原始、有出處」的資料；轉成遊戲用的
`js/seasons-data.js` 與物理校正由 `tools/build-cars.mjs` 負責，見最後一節〈遊戲資料與校正〉。

## 重新產生

```
node tools/build-seasons.mjs            # 有快取就直接用，沒有才下載最新版
node tools/build-seasons.mjs --refresh  # 丟掉快取，重新下載最新版
node tools/build-seasons.mjs --release v2026.15.1   # 指定版本
node tools/build-seasons.mjs --diag     # 列出每一場排位賽的量測值與過濾結果
node tools/build-seasons.mjs --quiet    # 不印各賽季表格
```

只需要 Node（18 以上，以 24 撰寫），沒有 npm 相依套件。同一份快取每次輸出完全相同。
腳本最後會跑 23 項查核，任何一項不符就以非零狀態結束。

## 輸出內容

頂層：`source`、`rules`（所有門檻值）、`straightLineSpeed`、`eraIndex`、`lineages`、`corrections`、`seasons[]`、`anomalies[]`。

每個賽季：`year`、`complete`、`races` / `racesScheduled`、`engineFormula`、`tyres`、`champion`、`driversChampion`、
`eraIndex`（外加 `eraIndexDirect`、`eraIndexFit` 兩個交叉檢查）、`medianPoleSpeedKmh`、`pace`（使用場次）、
`engineGroups`、`sessions[]`（每場排位的桿位時間、平均時速、分類、是否被排除及原因）、`entries[]`。

每個條目（`entries[]`）：

| 欄位 | 說明 |
| --- | --- |
| `id` | `<年份>-<constructorId>`，例如 `2010-red-bull`、`2021-mercedes`，符合 `/^[a-z0-9-]{1,40}$/` |
| `lineage` | 同一個組織跨年的鍵值（見下） |
| `constructor`、`entrants`、`country` | F1DB 的車隊名稱、該季的報名隊名、國籍 |
| `chassis`、`chassisAll` | 該季底盤型號 |
| `engineManufacturer`、`engineBuiltBy`、`engine` | 引擎掛牌名稱、實際製造者、型號 / 排氣量 / 汽缸排列 / 汽缸數 / 進氣方式 |
| `tyres` | 輪胎廠 |
| `standing` | 車隊積分榜名次與積分；`pointsScored` 是賽車實際拿到的分數（被扣分或除名時會不同） |
| `raceStarts`、`wins`、`poles`、`podiums` 等 | 由正賽成績統計，並與 F1DB 自己的賽季總計互相比對 |
| `drivers` | 車手與車號 |
| `pace` | 排位速度：`medianGapPct`、`sessions`、`rank`，另附平均值、最佳值與每場差距 |
| `character` | 高速 / 低速賽道的差異 |

## 規則

**條目**：依車隊積分榜，一個車隊一筆。2010–2026 每年 10–12 筆，合計 180 筆。

**lineage**：用 F1DB 的 `constructors-chronology` 把改名的車隊串成同一組，鍵值取該組在 2010 年以後最早出現的
constructorId。例如 `force-india`（Force India → Racing Point → Aston Martin）、`toro-rosso`（→ AlphaTauri → RB → Racing Bulls）、
`sauber`（→ Alfa Romeo → Kick Sauber → Audi）、`renault`（→ Lotus 2012–2015 → Renault → Alpine）、
`lotus-racing`（2010–2011 的 Lotus → Caterham）、`virgin`（→ Marussia → Manor）。2010 的 Lotus 與 2012 的 Lotus 屬於不同 lineage。

**排位速度**：每場取該車隊任一車手在 Q1 / Q2 / Q3 的最快單圈，算出與全場最快圈的百分比差距，再取整季中位數。
衝刺排位賽不計入。被淘汰在 Q1 的車隊只有 Q1 的圈速，賽道進化會讓差距略為偏大，這是這種算法的固有偏差。

**排除的場次**（344 場中排除 40 場，每季至少留 14 場）：

| 旗標 | 條件 | 場次 |
| --- | --- | --- |
| `slower-than-race-lap` | 桿位圈速沒有比正賽最快圈快（濕地排位） | 21 |
| `fastest-lap-in-q1` | 全場最快圈出現在 Q1（之後下雨，快車在 Q1 不會全力跑） | 11 |
| `q1-much-slower` | Q1 最快圈比全場最快圈慢 3% 以上（開頭濕滑，Q1 淘汰的車沒有代表性圈速） | 21 |
| `slow-vs-adjacent-seasons` | 比前後一年同賽道的預期慢 4% 以上 | 1（2021 比利時，正賽沒有計時圈） |
| `field-spread` | 全場中位差距異常放大 | 0（備用） |

一場可以同時有兩個旗標。另外，單一差距超過 12% 視為沒有代表性圈速而剔除（目前沒有任何一筆被剔除）。
`q1-much-slower` 的 3% 門檻離乾地最大值（2014 匈牙利 2.7%）很近，是經驗值；被留下的邊界場次可用 `--diag` 檢視。

**賽道性格**：每場以桿位平均時速（賽道長度 ÷ 桿位時間）與該季中位數比較，高於中位數為 `power`，低於為 `twisty`，
剛好等於中位數的那一場兩邊都不算。條目給出兩類的中位差距 `powerGapPct`、`twistyGapPct` 與差值 `twistyMinusPowerPct`。
最快的車在桿位時差距是 0，看不出強項，所以另外以「對該場中位車隊」的圈速重算一次，並扣掉全季中位數，得到 `vsFieldPct`：
正值代表在高速賽道相對較強（`lean: "power"`），負值代表在低速賽道相對較強（`"twisty"`），絕對值小於 0.10% 為 `"neutral"`。

**年代速度指數**：相鄰兩季中，賽道配置代號與長度都相同的賽道，取桿位時間比值的中位數，再以 2025 = 1.000 串接；
大於 1 表示比 2025 慢。每段的配對賽道數與各賽道比值在 `eraIndex.links`。

## 已知缺口

- **沒有直線速度資料**：F1DB 沒有測速點或最快圈時速（最快圈表只有圈數與時間），所以無法排出直線速度排名。
  最接近的指標是 `character` 與各引擎的中位數 `engineGroups`，但那是底盤加引擎的綜合結果。
- **`power` / `twisty` 只是平均時速高低**：高速彎多的賽道（Silverstone、Spa、鈴鹿）也會被分到 `power`，
  所以 `lean: "power"` 表示「在高速賽道較強」，不等於引擎馬力大。
- **2026 尚未結束**：23 站跑完 15 站，名次、積分、勝場與速度都是暫時的；指數由 14 條配對賽道算出。
  比賽繼續進行後以 `--refresh` 重新產生。
- **車隊名稱用 F1DB 的寫法**，與當年積分榜上的正式名稱不一定相同：2010 Sauber 的正式名稱是 BMW Sauber-Ferrari；
  2010–2011 的 `lotus-racing` 正式名稱是 Lotus；2018 Force India 在積分榜上是兩筆（除名的原車隊與 Racing Point Force India），
  這裡合併成一筆，名次與積分取後者（第 7、52 分），出賽與頒獎台涵蓋整季。這幾筆都有 `note`。
- **積分與實得分數不同的條目**：2018 Force India（52 分，賽車實得 111）、2020 Racing Point（195 分，實得 210，被扣 15 分）。
- **Toro Rosso 2017、BWT Mercedes 2019–2020 沒有引擎型號**，F1DB 只有掛牌名稱（`engine.designationIsBadge`）。
- **國籍是 F1DB 的車隊國籍**，例如 2019–2023 的 Alfa Romeo 記為義大利。
- **KERS / ERS、馬力、轉速、檔位數不在 F1DB 裡**，屬於年代規格研究（`docs/eras-research.md`）。
- 引擎型號只逐一查證了 2024–2026；更早的年份沿用 F1DB，未逐筆比對。

## 遊戲資料與校正（`js/seasons-data.js`、`js/cars.js`）

大獎賽先選年份（2010–2026），房間裡每個人再選那一年某支車隊的車。每一年有一輛「標準賽車」（該年代的物理，所有倍率為 1，
適合同車比賽），加上那一年車隊積分榜上的每支車隊（共 180 輛）。數字是依公開資料推估的遊戲數值，不是官方規格。

### 產生與檢查

```
node devtests/seasons-calib/calibrate.mjs    # 實車校正：自動駕駛實際開遊戲裡全部 40 條賽道（約 10 分鐘），寫 calibration.json
node tools/build-cars.mjs                    # 產生 js/seasons-data.js 與 devtests/seasons-calib/entries.json（約 40 秒）
node tools/build-cars.mjs --check            # 檢查兩個輸出是否為最新（test/cars.test.js 也會跑）
node devtests/seasons-calib/drive-check.mjs  # 每一年每輛車實跑 3 條賽道，排名相關係數（約 3 分鐘）
node devtests/seasons-calib/check-drive.js   # 獨立檢查：另一套自動駕駛（類比油門／煞車／方向）在 4 條賽道比對指數（約 3 秒）
node test/cars.test.js                       # 資料完整性、CarSpec、resolve 規則、2025 標準車 = F1.REF_SPEC、4 條賽道的指數
```

`check-drive.js` 不用產生器的任何程式：自己的自動駕駛依賽車線的速度曲線算出要的加速度，換成類比油門與煞車
（`input.throttle` / `input.brake`），方向用類比搖桿（`input.steerAxis`）純追蹤；預設開 Sepang、COTA、Jeddah、Zandvoort，
`--tracks` 換賽道，`--teams` 連車隊一起跑，`--json` 存結果。

`tools/build-cars.mjs` 只讀已提交的檔案（`tools/seasons-raw.json`、`tools/eras.json`、`tools/liveries/*.json`、
`js/cars-data.js`、`devtests/seasons-calib/calibration.json` 與遊戲本身的 `js/car.js`、`js/raceline.js`、`js/track.js`、
`tracks-data.js`），不連網路；同樣的輸入每次產生完全相同的檔案。`calibration.json` 記有校正前所有輸入的指紋
（設定、`F1.REF_SPEC`、各年校正前的物理、指數、參考車在每條校正賽道的賽車線圈速）；輸入一變，產生器就拒絕使用舊的校正，
要求重跑 `calibrate.mjs`。

### A. 年代物理（每年的標準車）

2025 年的標準車就是 `F1.REF_SPEC`（v5 的車，黃金規則的基準），逐位元相同。其他年份 = `F1.REF_SPEC` × 係數，
每個係數都是「該年數值 ÷ 2025 年數值」，資料來自 `tools/eras.json`：

| CarSpec 欄位 | 依據 | 做法 |
| --- | --- | --- |
| `power` | 排位重量的正賽配置功率重量比（內燃機 + 規則允許持續輸出的電力） | 比例 |
| `traction` | 加速區的功率重量比：2014–2026 用峰值（ERS 在出彎全開），2010–2013 用正賽配置 | 比例。遊戲車到約 317 km/h 都受牽引上限限制，所以這個數字就是它的加速力 |
| `dragK` | 不開 DRS 的典型極速（Monza 典型值減 FIA 的 DRS 增益） | 讓標準車的極速 = 330 km/h × 該年 ÷ 2025 年 |
| `latBase`、`brakeBase` | 機械抓地：胎面寬度比的 0.3 次方（輪胎負載敏感度：寬度加倍，抓地不會加倍） | × 校正的抓地倍率 |
| `latMax` | 最大側向 G | 比例 |
| `downforce` | 最大側向 G ÷ 機械抓地（高速彎靠下壓力） | × 校正的抓地倍率 |
| 檔位、轉速 | 2010–2013 七速，2014 起八速；V8：怠速 4500、換檔 17 800、上限 18 000；V6：怠速 4000、換檔 11 800（2026 為 11 500）、上限 15 000 | 最高檔在「放電極速」達到換檔轉速，最多比極速高 345/330（參考車的比例），取 5 km/h 整數；各檔依參考車的比例分布 |
| `shiftTime` | V8 用 eras.json 的 0.04 s；V6 沿用參考車的 0.05 s | 只影響聲音 |
| `ers` | 2010 無；2011–2013 KERS；2014–2025 = `F1.REF_SPEC.ers`；2026 350 kW | 見下 |
| `cockpit` | 2010–2017 `modern`、2018–2021 `halo`、2022 起 `halo18` | |

**抓地倍率**（下壓力、機械側向抓地、煞車抓地一起乘）是唯一的自由數字，用實車校正：標準車由 node 自動駕駛
（`devtests/seasons-calib/driver.mjs`：沿著為這輛車建的賽車線 `F1.buildRaceLine(track, car.perf)`，純追蹤轉向，油門與煞車
依賽車線的顏色，120 Hz，真正的 `js/car.js`，無輪胎模型 = 全新中性胎，不放電，不開限速器），在遊戲裡**全部 40 條賽道**
各跑 3 圈，取第 2、3 圈較快的一圈。倍率解到「40 條賽道上本年標準車 ÷ 2025 標準車」的中位數等於年代速度指數（誤差 0.03 %
以內；要求是 0.3 %）。起始值用賽車線速度曲線的模型解出，通常一次就中。

其他年份：

1. **目標圈速**：F1DB 排位差距（`pace.medianGapPct`）減掉全隊中位數，再壓縮到最快與最慢相差 1.25 %（與 2026 相同）：
   保留真實的順序與比例，標準車落在中位數的位置。
2. **引擎**：以實際製造者分組（`engineBuiltBy`：TAG Heuer 與 2017 Toro Rosso 是 Renault，BWT Mercedes 是 Mercedes），
   同組共用功率倍率 = 1 + 8 × 該組高速賽道傾向（`character.vsFieldPct` 中位數，%）/ 100，牽引另加上其中的 1/4；
   只有一支車隊用的引擎，傾向只算一半給引擎。例：2014 Mercedes +1.6 %、Renault −1.6 %；2018 Renault −3.6 %。
3. **尾翼角度**：車隊自己的傾向減掉引擎組的傾向，每 1 % 讓風阻與下壓力各減 5 %（偏高速賽道的車跑較少的尾翼）。
4. **底盤水準 L**：抓地、煞車、牽引與下壓力一起 + L（同 2026 的做法），用賽車線速度曲線模型在全部 40 條賽道上
   解到平均圈速差等於目標。
5. ERS 倍率一律 1（這些年份沒有可查證的來源）。所有倍率都在 0.95–1.05 之內，取四位小數。
6. **評分**（0–100，50 = 該年標準車）：與 `js/cars-data.js` 同一個公式（極速每 km/h 11 分、加速每 % 12 分、過彎每 % 23 分、
   煞車每 % 20 分、ERS 每 % 13 分）。唯一的調整：加速是「0 到 300 km/h × 該年標準車極速 / 330」的時間，2025 與 2026

### `js/cars.js`

`F1.cars.seasons`、`list(year)`、`get(id)`、`resolve(id, year?)`、`DEFAULT_YEAR`（2026）、`attribution`
（`f1db`：F1DB 完整標示，含 CC BY 4.0 與「modified」；`f1dbShort`；`sources2026`；`disclaimer`）。CarSpec = 年代值 × 倍率，
逐欄檢查，範圍與 `js/car.js` 的 `F1.sanitizeSpec` 完全相同（物理是參考車的 1/4–4 倍、ERS 1/10–10 倍、檔位 10–500 km/h、
轉速、換檔時間、汽缸數），年代值與「年代值 × 倍率」都檢查；倍率夾在 0.95–1.05；壞掉的資料退回參考車的值，不會出現 NaN，
而且每個 CarSpec 都正好是 `js/car.js` 會開的車（`F1.sanitizeSpec(spec)` 與 spec 完全相同，測試裡用隨機損壞的資料驗證），
HUD、聲音與物理不會各用各的數字。建立一次後凍結（共用，要改請先複製）。
`resolve`：同一年的車直接回傳；否則找同一個 lineage（例如 Toro Rosso → AlphaTauri → RB → Racing Bulls）在那一年的車；
那年沒參賽就回傳那年的標準車。沒有年份字首的 id（`js/cars-data.js` 的 `mercedes`、lineage 鍵、`standard`）視為那支車隊；
沒給年份（或不是賽季的年份）時，已知的 id 用它自己的年份，其他用 `DEFAULT_YEAR`。id 與年份來自網路，查詢一律用 `Map`，
像 `constructor` 這樣通過 `/^[a-z0-9-]{1,40}$/` 的字串也不會碰到物件原型。

### 決定與取捨

- **校正的是「抓地倍率」而不是只有下壓力**：只調下壓力時，這個模型的圈速對下壓力不敏感，2026 要降到 ×0.49、2020 要升到
  ×1.27 才對得上指數，不合理；下壓力、機械抓地與煞車抓地一起調，幅度落在 ×0.92–1.04。
- **功率照 eras.json**：eras.json 的 2014 年正賽配置功率重量比（815 W/kg）低於 2013（876 W/kg，車輕 50 kg），所以遊戲裡 2014
  的 `power` 比 2013 低；但 2014 的車風阻低很多（極速 335.8 對 318.4 km/h）、電池強得多（145 對 91 W/kg、32 對 6.4 s），
  放電時的總功率與直線速度都高於 2013。這與任務說明裡「2014 功率高於 2013」的例子不同，依照「數字不合時調整空力、不動功率」處理。
- **2026 的牽引用峰值功率重量比**（350 kW 在加速區全開），功率用正賽配置值，所以 2026 出彎強、長直線尾段弱，符合實際
  （匈牙利測速點比 2025 快 22 km/h、Monza 慢 18 km/h）。
- **V6 轉速上限 15 000**（任務要求，也是規則值），但 2025 必須等於 `F1.REF_SPEC`，保留 12 500。換檔聲音時間 V6 沿用參考車的
  0.05 s（eras.json 的遊戲值是 0.03 s），避免 2024 與 2025 不一致。
- **年份標籤** = 年份 + eras.json 的時代說明（例如「2014 · V6 渦輪混合動力第一代：8 速、ERS」），因為選單在標籤旁邊
  已經顯示引擎字串（`engine`，例如「1.6 L V6 渦輪混合動力」），標籤再寫引擎會重複。
- **標準車的說明一律空白**：2025 的標準車必須與 `F1.REF_SPEC` 完全相同（`note: ''`）。
- 每季的車資料多了 `lineage`（`resolve` 用）與 `est`（模型估計的圈速差與極速），季資料多了 `paceIndex`；標示文字放在
  `window.F1_SEASONS_INFO`。這些都是介面契約之外的附加欄位，CarSpec 本身只有契約裡的欄位。

### 限制

- 圈速差是「自動駕駛 + 遊戲模型」下的數字：沒有 DRS、沒有油量、輪胎只有全新中性胎、每個年代只有一個抓地倍率。
- 2026 年賽季尚未結束，指數與車隊倍率都是第 15 站後的暫時值。
- 真實的年代差異隨賽道而變，遊戲只對齊全部 40 條賽道的中位數；單一賽道最多偏離約 2.6 %（2014、2026），任意 4 條賽道的中位數
  可能偏離 0.5 % 左右。遊戲裡各賽道的型態（低下壓力年份在高速彎賽道慢、在 Monza／摩納哥／街道賽快）與真實桿位的各賽道型態
  相關性很弱（0.21）。最明顯的是 2026：在真正比過 2025→2026 的 14 條賽道上，遊戲的中位數比值是 1.026，真實是 1.032
  （遊戲的 2026 在 Monza、Red Bull Ring、摩納哥相對太快，在匈牙利、Zandvoort、Barcelona 相對太慢）。原因在車的模型：
  只有一個牽引上限（2026 的 ×1.115 同時讓低速出彎的輪胎牽引變強，雖然 2026 的輪胎較窄），也沒有「長直線電力用完、尾段掉速」。
  換成任何一組校正賽道都無法同時修好；指數本身的不確定度（逐年串接、直接比對、整體擬合三種算法）也有 0.5–1 %。
