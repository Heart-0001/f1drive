
################ Chinese track names

== summary
Wrote js/track-names-zh.js. It is a classic script that sets window.F1_TRACK_NAMES_ZH and also exports through module.exports for node. Every id in tracks-data.js has one entry of the form { name, short, location, aliases }. The display fields (name, short, location) follow the forms Taiwanese F1 coverage uses. The main source is 運動視界 Sports Vision's 'F1賽道簡介' series: I downloaded all 27 articles and counted which '…賽道' forms they use. The other sources are U-CAR F1's season calendars for GP and country names, plus 聯合報 / 自由時報 / ETtoday / 中央社 hits. zh-tw Wikipedia titles, fetched through the MediaWiki API with varianttitles, were used as a cross-check, and as the fallback where Taiwan has no established form.

Examples: 鈴鹿賽道, 蒙札賽道 (Sports Vision uses 蒙札; 蒙扎 is only an alias), 紐柏林賽道, 銀石賽道, 斯帕-法蘭柯爾尚賽道, 亞伯特公園賽道, 英特拉哥斯賽道, 贊德沃特賽道, 羅賽爾國際賽道, 吉達濱海賽道 and 亞斯碼頭賽道. Countries and cities use Taiwan forms: 澳洲, 義大利, 沙烏地阿拉伯, 卡達, 亞塞拜然, 蒙特婁, 伊斯坦堡, 阿布達比, 摩納哥 蒙地卡羅.

The aliases are for search only (243 in total). They cover the zh-tw Wikipedia form where it differs, other spellings found in Taiwanese media, mainland and Hong Kong forms in simplified and traditional characters, and a few ASCII forms for names with diacritics or abbreviations (Portimao, Nurburgring, Jacarepagua, Galvez, Hermanos Rodriguez, COTA). Every name or short that contains a middle dot also has an alias without the dot.

Validation (scratchpad/validate.js) loads the file both as a classic script in a vm with a window object and through require(), and the two results are identical. All 40 ids are present exactly once; this is checked against the raw source text too, because duplicate object keys would otherwise disappear silently. There are no unknown ids and no empty or untrimmed fields. Aliases have no duplicates and never repeat name, short or location. name, short and location contain no simplified-only characters, no mainland terms and no Latin letters. Every location has the form '<country> <place>'.

A simulated search uses the same key as js/ui.js: English name + location + id, plus the Chinese fields, lower-cased. Run with plain substring matching (which ui.js uses today), all 53 test queries find the right track: 鈴鹿, 铃鹿, 鈴鹿國際賽車場, 蒙扎, 纽博格林, portimao, cota and others. Every name and every short finds its own card. Running the 11 node test suites was not needed: no test loads this file and no other file was touched. package.json already packages js/*.js. Nothing was committed.

== summary
I checked js/track-names-zh.js on its own and now own it. Suzuka is there: jp-1962 is 鈴鹿賽道 / 鈴鹿 / 日本 鈴鹿, with 鈴鹿國際賽車場, 鈴鹿賽車場, 铃鹿 and 铃鹿赛道 as aliases. All 40 ids in tracks-data.js appear exactly once, in both the parsed object and the raw source text. There are no unknown ids.

How I checked:
- I got the zh-tw Wikipedia title for every circuit and place through the MediaWiki API (variant=zh-tw, starting from the English articles' langlinks).
- I recounted the forms in each Sports Vision article the file cites (the cached pages, plus 105133 fetched again).
- I spot-checked Taiwanese media: CNA 202211010118, ETtoday 20240401/2710938, UDN 8324/3957358 and 8324/1867441, and LightsOut.

Most display forms held up. Two display forms changed:
1. **de-1932 Hockenheim:** 霍根海姆賽道 / 霍根海姆 / 德國 霍根海姆 became 霍肯海姆賽道 / 霍肯海姆 / 德國 霍肯海姆.
   - 霍根海姆 is the form Baidu and other mainland sites use.
   - The Sports Vision article cited for it (65577) was written by Red Bull. The circuit's article in Sports Vision's own circuit-guide series (32372) uses 霍肯海姆 ten times.
   - ETtoday (2024) also uses 霍肯海姆.
   - zh-tw Wikipedia's title is 霍肯海姆賽道, and its regional-names table lists 臺灣 霍肯海姆. The file had claimed Wikipedia used 霍根海姆, which was wrong.
   - 霍根海姆, 霍根海姆賽道 and the Hong Kong form 賀根咸 are now aliases.
2. **qa-2004 Lusail location:** 卡達 盧賽爾 became 卡達 盧塞爾. The file cited CNA for 盧賽爾, but CNA writes 盧塞爾 (盧塞爾地標體育場). 盧賽爾 and the mainland 卢赛尔 are now aliases.

Other fixes, without changing any card text:
- Five Wikipedia forms the file quoted were the unconverted (mainland-character) titles, not zh-tw. Corrected:
  - Monza: zh-tw 國立蒙札賽車場
  - Zandvoort: zh-tw 贊德沃特賽道
  - Estoril: zh-tw 埃斯托里爾賽道
  - Nürburgring: zh-tw 紐柏林賽道, village 紐堡
  - Spielberg: zh-tw 斯皮爾堡
- Two more source notes were wrong:
  - Paul Ricard: zh-tw Wikipedia is 保羅·理察賽道, not 保羅·里卡爾.
  - Spa: Sports Vision 33257 writes 法蘭科爾尚; 法蘭柯爾尚 comes from 105133 and 19925.
- New search-only aliases: 國立蒙札賽車場, 埃斯托里爾賽道, 保羅·理察賽道, 保羅理察賽道, 斯皮爾堡, 墨西哥市 (CNA's general form), 賀根咸, 卢赛尔.
- The header comment now tells the UI owner to treat other middle dots as '·'. Those are '‧' (U+2027, what Taiwanese keyboards usually produce), '．' (what Sports Vision writes), '・', '･' and '•'. It also says to treat the dashes '–', '—' and '－' as '-'.

The other agent's validator, extended with 10 new search queries and 霍根海姆 / 盧賽爾 added to the list of forms banned from display fields, passes. It loads the file both as a browser script and through require(), and the two give the same data. There are 251 aliases, and every name and short finds its own card. `node --check` also passes. I touched no file other than js/track-names-zh.js and committed nothing.
